# UI Guide

## 디자인 방향
`EOL Diagnostic Tester`는 작업자 친화적인 현대적 산업용 Windows 앱이어야 한다.

목표는 구시대적인 WinForms 느낌이 아니라, Windows 11/Fluent UI 계열의 정돈된 데스크톱 도구다. 다만 화려한 마케팅 화면이 아니라 현장 작업자가 빠르게 상태를 읽고 실수 없이 조작할 수 있는 UI를 우선한다.

## 핵심 원칙
- 작업자는 CAN/UDS 세부 지식을 몰라도 사용할 수 있어야 한다.
- 화면마다 가장 중요한 행동이 명확해야 한다.
- 장비 상태, 현재 진행, OK/NG, 실패 사유가 즉시 보여야 한다.
- 설정, EOL 기능, 공통 도구를 명확히 분리한다.
- 테이블은 정보 밀도가 있어야 하지만 읽기 쉬워야 한다.
- 불필요한 장식, 과한 애니메이션, 마케팅식 hero layout은 사용하지 않는다.

## 전체 화면 흐름

```text
모델 선택
  -> 검사 준비
    -> 기능 메뉴
      -> 자동검사 / 수동 기능 / 결과 리포트 조회
```

모델 선택 이후에는 사이드 메뉴를 제공한다.

```text
검사
- 검사 준비
- 기능 메뉴

설정
- CAN Setting
- 기능 Setting

도구
- 통신 모니터링
```

별도 `로그` 메뉴는 MVP에서 제공하지 않는다. 필요 시 통신 모니터링 안에서 확장한다.

## 공통 레이아웃

### 상단 상태 영역
모든 주요 화면에서 설정된 Driver 기준의 장비 상태를 표시한다.

```text
장비 상태: 연결됨
장비 상태: 미연결
```

장비 상태는 상세 CAN 설정값을 항상 보여주기 위한 영역이 아니다. 작업자에게는 연결/미연결만 명확히 보여준다.

### 사이드 메뉴
모델 선택 화면에는 사이드 메뉴를 표시하지 않는다.

검사 준비 이후에는 사이드 메뉴를 표시한다.

- 검사
- 설정
- 도구

기능 메뉴 안에는 실제 EOL 기능만 배치한다. CAN Setting과 통신 모니터링은 기능 메뉴에 넣지 않는다.

## 화면별 가이드

### 모델 선택
초기 화면은 단순해야 한다.

표시:
- 앱 이름
- 모델 선택
- `Mower / RFS120S`
- 다음 버튼

표시하지 않음:
- CAN 상태 상세
- 검사 항목 목록
- 모델 설정 상태 카드
- 사이드 메뉴

### 검사 준비
작업자가 검사 전에 입력해야 하는 최소 정보를 받는다.

표시:
- 모델: `Mower / RFS120S`
- VIN 입력
- 작업자 입력
- 장비 상태: `연결됨 / 미연결`
- 기능 메뉴로 이동 버튼

동작:
- VIN은 필수다.
- 작업자는 권장 입력이다.
- 장비가 미연결이면 기능 메뉴로 이동할 수 없다.
- 장비 미연결 시 설정으로 이동할 수 있는 링크 또는 버튼을 제공한다.
- CAN Setting 전체를 검사 준비 화면에 펼쳐놓지 않는다.

### 기능 메뉴
실제 EOL/진단 기능만 표시한다.

항목:
- 자동검사
- 시스템 사양정보
- 현재 고장 진단
- 과거 고장 진단
- 고장 소거
- 강제구동
- 리프로그래밍
- 프리즈 프레임 조회
- 결과 리포트 조회

`리프로그래밍`과 `프리즈 프레임 조회`는 MVP에서 준비 중 상태로 표시한다.

### CAN Setting
설정 영역에 배치한다.

표시:
- Driver: Kvaser / PEAK / Simulator
- CAN Type: Classic CAN / CAN FD
- Classic CAN bitrate
- CAN FD arbitration bitrate
- CAN FD data bitrate
- BRS
- ISO CAN FD
- ID Type: Standard 11-bit / Extended 29-bit
- TX ID
- RX ID

표시하지 않음:
- 별도 장비 연결 상태 상세
- 작업자용 자동검사 결과

검증:
- Standard 11-bit ID: `0x000` ~ `0x7FF`
- Extended 29-bit ID: `0x00000000` ~ `0x1FFFFFFF`
- CAN FD 선택 시 data bitrate 필수
- TX/RX ID 비어 있으면 저장 불가

### 시스템 사양정보
`ReadDataByIdentifier(0x22)` 결과를 테이블로 표시한다.

권장 컬럼:
- NO
- 항목명
- 값
- 상태

개발자 상세 보기에서는 DID 또는 raw data를 볼 수 있게 확장 가능하다.

버튼:
- 읽기

초기화 버튼은 제공하지 않는다.

### 현재 고장 진단
수동 조회 화면에서는 DTC 존재가 NG가 아니다.

권장 컬럼:
- P-Code
- 고장 내용
- Severity

DTC가 없으면 명확히 표시한다.

```text
현재 고장이 없습니다.
```

### 과거 고장 진단
권장 컬럼:
- P-Code
- 고장 내용
- Severity
- 발생 시간
- 발생 횟수

발생 시간과 working time은 ECU에서 second로 올라온 값을 사람이 읽기 쉬운 형식으로 표시한다.

```text
2h 3m 4s
```

상세 데이터에는 원본 second 값을 보관한다.

### 고장 소거
고장 소거는 위험한 기능이므로 확인 팝업이 필요하다.

문구 예:

```text
현재 및 과거 고장 코드를 소거합니다.
계속하시겠습니까?
```

Positive Response면 소거 완료를 표시한다.

### 강제구동
테이블 중심으로 구성한다.

권장 컬럼:
- 강제구동 항목
- 시간
- 제어
- 결과

상태:
- N/A
- RUN
- OK
- NG

버튼:
- 개별 시작
- 전체 순차 실행
- 전체 정지

기본 정책:
- 기본 실행 시간 4초
- 항목 간 텀 1초
- 전체 순차 실행은 8개 항목만 실행
- ALL ON은 순차 실행에서 제외
- 일반 NG는 표시 후 다음 항목 진행
- 전체 정지 시 현재 RUN 항목에 Stop 시도

### 자동검사
자동검사 화면은 진행 상태 표시보다 실제 결과 누적 표시가 중요하다.

상단:
- 현재 단계
- 진행률

본문:
- 단계별 결과 패널을 표시한다.
- 완료된 단계의 실제 결과를 계속 유지한다.
- 아직 실행 전 단계는 대기 상태 또는 빈 결과로 표시한다.
- NG가 있으면 실패 사유를 표시한다.

단계별 패널:
- 시스템 사양정보 결과 테이블
- 현재 고장 진단 P-Code 테이블
- 고장 소거 결과 메시지
- 과거 고장 진단 P-Code 테이블
- 강제구동 항목별 결과 테이블

raw TX/RX:
- 기본 숨김
- 각 단계의 상세 보기에서 확인 가능
- NG 단계는 실패 사유를 기본 표시한다.

### 결과 리포트 조회
현재 선택 모델(`Mower / RFS120S`)의 저장된 리포트만 조회한다.

기능:
- 날짜 범위 검색
- VIN 검색
- 작업자 검색
- 결과 필터
- 선택 리포트 미리보기
- PDF 열기
- JSON 기반 PDF 재생성

### 통신 모니터링
공통 도구 영역에 둔다.

MVP 기능:
- CAN trace 실시간 표시
- timestamp
- direction
- CAN ID
- DLC
- data bytes
- pause/resume
- clear
- ID filter

Manual Transmit은 MVP에서 제외한다.

## 시각 스타일

### 톤
- Windows 11/Fluent UI 계열
- 산업용 검사 대시보드
- 신뢰감 있고 정돈된 UI
- 과한 장식 없이 선명한 상태 표현

### 색상
- 배경: 밝은 작업 영역 + 차분한 다크 사이드바
- OK: green
- NG: red
- RUN: blue 또는 amber
- N/A: neutral gray
- 경고/확인 필요: amber

### 컴포넌트
- StatusBadge
- DeviceStatusBar
- StepResultPanel
- ResultTable
- PrimaryButton
- SecondaryButton
- ConfirmDialog
- ReportPreview
- TraceGrid

### 버튼
- 주요 행동은 명확한 primary 버튼으로 표시한다.
- 파괴적 또는 위험한 기능은 확인 팝업을 사용한다.
- 버튼 텍스트는 동작 중심으로 작성한다.

예:
- 읽기
- 고장 소거
- 전체 순차 실행
- 전체 정지
- 저장하기
- PDF 열기

### 테이블
- 행 높이는 너무 크지 않게 유지한다.
- 상태 컬럼은 badge를 사용한다.
- 긴 설명은 줄바꿈 또는 tooltip을 제공한다.
- 작업자용 테이블에는 raw hex 값을 기본 표시하지 않는다.

## 접근성 및 사용성
- VIN 입력 후 Enter로 다음 행동이 가능해야 한다.
- 장비 미연결, 저장 안 됨, NG 사유 같은 중요한 상태는 색상만으로 전달하지 않고 텍스트도 함께 표시한다.
- 검사 중 장비 연결 해제 시 명확한 안내 후 모델 선택 화면으로 복귀한다.
- 저장하지 않은 리포트가 있으면 이탈 전 확인한다.
